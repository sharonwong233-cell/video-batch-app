# V1.4 修改与验收

日期：2026-09-10。对应本次四项修改，不新增第三方依赖；按 ponytail 复用项目模型、原生复选框、FFmpeg 与已有自测入口。

## 变更

1. **拼接、画面适配可以独立勾选或取消。** 修改保存至项目设置 `concat` / `fit`，重开恢复。摘要、预检、真实预览、实际导出读取同一设置。取消拼接后按每个视频分别计时分段，结果全局连续编号；取消适配后保留各视频画面尺寸。
2. **新项目默认 45 分钟。** 界面初始值、项目默认值、缺省解析统一修改，仍可自行输入。已有项目明确保存的 30 分钟等值不被覆盖。
3. **无打码优先直接复制。** H.264/H.265 视频及 AAC/无音轨、参数兼容且不需适配时直接复制，不视频重编码。隐藏的打码区域不触发编码。取消拼接时按视频独立判断，某个视频需编码不会连带所有其他视频。编码/帧率/音轨等参数不兼容，或需要实际适配时，在确认窗口提示容错重编码。
4. **结果页用时。** 原“实际输出”标记替换为“输出用时：XX分XX秒”。采用单调时钟，计算从任务开始至处理、验证、写入、清理结束的时间，不受系统时间调整影响，完成后冻结。超过一小时显示累计分钟。

## 异常处理与限制

- 直接复制不等于跳过检查：输出逐段解码核验，发现复制、解码或格式异常会自动重试容错解码 + H.264 软件重编码。进度和结果页面保留警告。容错使用 FFmpeg 的 `genpts` / `discardcorrupt` / `ignore_err`，可能丢弃损坏帧或修复时间戳，并不保证修复所有损坏素材；仍无法生成合格结果时报告失败，不发布残缺视频。
- 解码核验会消耗时间，但没有视频重编码；无损路径不会走画面滤镜或编码器。AAC 在拼接边界可能存在编码填充造成的轻微时间戳重叠，由封装器整理，再检查输出；不会仅因为这种正常边界就全量重编码。
- 关闭画面适配，却要求把不同尺寸视频拼成一个固定尺寸视频，条件互相冲突。本版会明确要求开启适配或取消拼接，不擅自缩放、拉伸、裁切。开启适配时不同尺寸可自动重编码统一。
- MP4 无损兼容路径目前覆盖 H.264/H.265 + AAC/无音轨。其他编码会提示并重编码，不保证所有容器内的所有视频流都能直接装入 MP4。
- 同名文件、磁盘空间、读写权限、取消不会被当成损坏码流反复重试。重試前清理本次失败尝试的临时文件；源文件不改变，所有片段核验通过后才发布。
- HDR 如需重编码会拒绝自动改变色彩，提示先转换 SDR；不新增 HDR 色调映射。

## 验证

最终本机结果：40 项引擎检查、21 项桌面集成检查全部通过。

引擎自测：`selftest.cjs`。新增覆盖 45 分钟默认值、旧项目迁移、开关持久化、独立分段尺寸和音轨保留、单视频压缩数据逐包一致、兼容拼接的解码画面逐帧一致、H.265 保持原编码、真实损坏 NAL 触发回退、实际耗时完成后冻结，以及临时目录清理。

桌面集成：`native-acceptance.cjs`。检查真实点击取消/再次勾选、摘要和冲突提示、预检参数、取消拼接与适配后的真实输出尺寸、自动保存和重载、用时显示和冻结；同时回归播放、快进快退、打码和真实导出。

运行引擎自测：`node selftest.cjs`，或使用 Electron 内置 Node。桌面验收：`Electron windows版 --acceptance-test --acceptance-dir=<引擎自测输出目录> --user-data-dir=<独立测试用户目录>`。

验收报告、截图和样例位于 `验收记录/V1.4/`。本机验证环境为 macOS + 相同 Electron 应用代码；Windows 包校验架构、内容和 ZIP 完整性，不代替 Windows 真机驱动验收。

FFmpeg 参数依据：[格式选项](https://ffmpeg.org/ffmpeg-formats.html#Format-Options)、[解码错误检测](https://ffmpeg.org/ffmpeg-codecs.html#Codec-Options)、[命令行错误退出](https://ffmpeg.org/ffmpeg.html)。
