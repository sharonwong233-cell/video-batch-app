# V1.4.1 时间线修复

日期：2026-09-10；基于 V1.4，保留原版本 ZIP。未新增依赖，未更改视频导出引擎。

## 修改内容

1. 视频轨道原先使用含固定基础宽度、最小宽度和间距的弹性布局，而打码轨道使用百分比定位且有额外内边距。改为按全项目累计秒数定位，统一起点、宽度与时间比例。
2. 视频片段、打码时间条、刻度与播放指针共用一个无水平内边距的时间平面；移除挤占时间宽度的片段间距和最小宽度。短片段真实宽度不会被标题撑大，可放大时间线查看；悬停可查看完整标题。
3. 刻度固定为 00:00:00、00:15:00、00:30:00……，仅显示项目范围内的刻度。不是每隔四分之一总时长取点。较长项目保证刻度有足够间距，超出视口整体横向滚动。
4. 提供 1×、2×、4×、8× 时间线缩放，所有轨道同步；窗口改变大小时重新计算同一个平面的宽度。多区域的纵向滚动也位于公共容器，不再单独缩窄打码轨道。
5. 播放头显示全局时间；播放器时间仍为当前素材的局部时间。打码标签仍使用所属素材的局部生效时间。
6. 拖动打码区域及两端，使用公共时间平面的实时位置和宽度换算时间，计入横向滚动。附带修复：视频定位完成后恢复真实预览按钮的可用状态。

## 验收方法

- `timeline-acceptance.cjs` 在真实 Electron 桌面中检查边界坐标（允许小于 0.12 CSS 像素的布局取整误差）。长时素材采用时长夹具，不宣称完成数小时视频导出测试。
- 覆盖 1100、1440、1920 像素窗口，四档时间线缩放，滚动起点和末端，应用 80%/125% 缩放，多打码轨道纵向滚动、极短素材、终点恰为15分钟刻度、空项目。
- `native-acceptance.cjs` 使用真实视频，覆盖快进、快退、进度定位、播放、两个缩放档位下滚动后的时间条左右端与整体拖动、真实预览、真实导出、保存恢复。拖动通过桌面渲染器的 PointerEvent 驱动处理函数，不代替 Windows 鼠标实机验收。
- 验收记录位于 `验收记录/V1.4.1/`。坐标检查已通过 1740 次断言，29 项真实视频桌面回归检查全部通过，包含实际输出文件的解码核验。

## Windows 使用

完整解压 `FrameFlow-v1.4.1-Windows-x64.zip` 到新文件夹，然后启动其中的 `FrameFlow.exe`，不要在 ZIP 预览中直接启动，也不要仅替换 exe。依赖已内置。

本机验证平台为 macOS 上的 Electron；Windows 包使用相同的页面和交互代码，仍需 Windows 实机验收鼠标操作、显示缩放与驱动兼容性。
